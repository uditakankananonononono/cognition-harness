This supersedes proposal f1efa230, not the earlier arithmetic protocols. No pilot tasks have been scored. Runtime feasibility probes contain no data-repair task or evaluator examples. Scope: local JSON transformation methods, descriptive composition transfer only, no scientific discovery, paid service, model, real account, activation or public final pack.

## 1. Versioned public interface and exact semantics

Invocation: solve(spec,records). Wire input is one UTF-8 JSON object with EXACT keys spec and records. Strict JSON parsing rejects NaN/Infinity, duplicate object keys and trailing content. Output must be one JSON object and nothing else.

spec has EXACT keys version and steps. version is integer1 (not bool); steps is a list of0..6 exact-schema operators below. Field addressing top-level string keys only, no path syntax. Field names1..64 Unicode characters. Unknown spec/operator properties, unsupported policy values and wrong property types return invalid_spec. Unknown string op returns unsupported ONLY when version and top-level schema are otherwise valid; scan all steps for invalid shape/fields first, invalid_spec takes precedence over unsupported. Unknown/noninteger version returns invalid_spec.

Each operator has exact required keys; no implicit policies:
* select: op, fields(list of unique field names), missing('omit'|'null'|'error'). Output a dict for each row with fields in requested order; missing omit drops key, null inserts null, error -> missing_field. Empty fields allowed.
* rename: op, mapping(dict source name->destination name), missing('ignore'|'error'), collision('error'|'overwrite'). Simultaneous renaming from original row. Mapping targets must be unique, else invalid_spec. Unmapped fields retain names. Output preserves original field traversal order with renamed labels, but object key order is not scored. A renamed target conflicts with an unmapped retained field: error -> rename_collision; overwrite -> renamed value wins regardless source order. Missing source ignore leaves row unchanged for that source; error -> missing_field. Renaming cycles permitted, simultaneous.
* filter: op, field, relation('eq'|'ne'|'lt'|'le'|'gt'|'ge'), value(JSON scalar), missing('drop'|'error'), nonnumeric('drop'|'error'). For eq/ne use recursive exact typed equality (value limited scalar). bool distinct int distinct float; -0.0 equals0.0 same float, no sign-bit identity; int0 distinct float0.0. Absent field drop or missing_field; null is present. Numeric relations permit int/float but exclude bool and all nonnumbers; int/float compare mathematically using Python3.10 numeric comparisons, no conversion to float. Nonnumeric includes null: drop or nonnumeric_value. For eq/ne nonnumeric policy is declared but inert; no unknown fields accepted.
* sort: op, field, direction('asc'|'desc'), missing('first'|'last'|'error'), mixed('rank'|'error'). Stable. Missing bucket position independent direction; error -> missing_field. Present null is not missing. Type rank ascending: null,bool,int,float,string,list,dict. Direction reverses value/type-rank order but never original tie order. mixed error rejects if more than one present exact JSON type (int vs float counts mixed), mixed_type error. Within null all equal; bool false<true; ints/floats numerical order (finite only); strings Python Unicode code-point order; lists/dicts ordered by deterministic canonical typed JSON string described below. Same-type equal numeric values incl-0.0 tie. Dict key ordering irrelevant; canonical keys sorted Unicode. Empty input valid.
* dedup: op, fields(list of unique field names), missing('distinct'|'null'|'error'). Typed key vector in field order, first matching row retained, original row unchanged. Missing distinct inserts a special missing sentinel distinct from null, not a unique row-ID; two missing sentinels equal each other. null converts missing to null. error -> missing_field. Empty fields -> all rows share empty key, keep first. Equality recursive exact types, dict order ignored, finite float-0.0 equals0.0, int/float differ.
* group_count: op, fields(list unique names), missing('distinct'|'null'|'error'). Same typed key vector/sentinel rules. Stable group order by first occurrence. Replace records with list of objects EXACT keys key and count: key is list of objects {present:boolean,value:JSON}; missing-distinct -> {present:false,value:null}, otherwise {present:true,value:actual/null}. count positive integer. Empty fields creates one group if any input, none if empty. Further operators can address key/count top-level.

Canonical typed JSON for sort list/dict: each node is [type-tag, payload], tags null,bool,int,float,str,list,dict; integer payload decimal string; float payload repr with negative zero normalized to'0.0'; list payload recursive node array; dict payload sorted [key,typed-node] pairs. Serialize ensure_ascii=False,separators(',',':'), finite only. Only compares within list/list or dict/dict; it is a declared lexical order, not numeric list ordering.

Records: list<=100 dict rows, max JSON depth5 counted record-object depth0 and each child+1; strings<=1000, keys field name lengths not constrained outside spec references except1000 max. Every container<=100 entries, input UTF-8 bytes<=1MiB. Bool/int/finite-float/string/null/list/dict allowed; nonstring dict keys cannot occur valid JSON. Numeric strings are not numbers. Empty input, empty row, error-producing inputs stay in denominator.

Result envelope EXACT {'status':'ok','records':<list>} OR {'status':'error','code':<string>}. Codes: invalid_spec,unsupported,invalid_records,missing_field,rename_collision,nonnumeric_value,mixed_type,output_limit. Validate spec BEFORE records, then steps execute in order and first error ends task. Whole input-record validation before any transform; bounds/nonfinite -> invalid_records. Unsupported detected before records validation after invalid_spec scan. Output same bounds and1MiB cap; if transform exceeds bounds -> output_limit. Runtime exception/timeout/process failure/malformed JSON is an execution violation, NOT a correct declared error. No extra output fields, bool counts not integers. Expected errors are legitimate exact-scored outcomes only when reference calls for them.
